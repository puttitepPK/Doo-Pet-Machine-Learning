## 1. กำหนดโจทย์ว่าต้องการให้โมเดลตอบอะไร

## 3. สำรวจข้อมูลก่อนฝึก หรือ EDA

EDA ย่อมาจาก Exploratory Data Analysis คือการสำรวจว่าข้อมูลที่มีอยู่หน้าตาเป็นอย่างไร

โน้ตบุ๊กใช้ข้อมูลในตาราง `inventory.csv` และกราฟเพื่อตรวจเรื่องต่อไปนี้:

- แต่ละแหล่งและแต่ละกลุ่มมีภาพกี่ภาพ
- มีไฟล์ที่เปิดไม่ได้หรือไม่
- ขนาดภาพ อัตราส่วนภาพ และโหมดสีเป็นอย่างไร

## 4. ทำความสะอาดและปรับชื่อกลุ่มให้ตรงกัน

ข้อมูลแต่ละแหล่งอาจใช้ชื่อกลุ่มต่างกัน จึงต้องสร้างกติกาจับคู่ชื่อให้เป็นมาตรฐาน ตัวอย่างในโน้ตบุ๊ก:

```text
fungal infection ──→ fungal_infection
ringworm ─────────→ fungal_infection

hypersensitivity dermatitis ──→ hypersensitivity
```

มีการตัดกลุ่มบางกลุ่มที่มีข้อมูลน้อย และจัดการภาพซ้ำด้วยสองวิธี:

| วิธี | ใช้ตรวจอะไร |
|---|---|
| MD5 | ไฟล์ที่มีเนื้อหาไบต์เหมือนกันทุกประการ |
| pHash | ภาพที่มีลักษณะคล้ายกัน แม้ไฟล์จะไม่เหมือนกันทุกไบต์ |

กฎสำคัญคือแยกภาพซ้ำหรือคล้ายที่ติดป้ายขัดแย้งข้ามกลุ่มออก และเก็บสำเนาเดียวของภาพที่ MD5 ซ้ำภายในกลุ่มเดียวกัน ภาพที่ตัดออกถูกย้ายไปพื้นที่แยกพร้อมบันทึกเหตุผล ไม่ได้ถูกนำไปเรียนรู้ในชุดสุดท้าย

**สิ่งที่ได้ตามผลในโน้ตบุ๊ก:** ภาพหลังทำความสะอาด **13,415 ภาพ ใน 6 กลุ่ม**

## 7. เตรียมภาพให้เป็นตัวเลขที่โมเดลรับได้

สำหรับ MobileNet ในโน้ตบุ๊ก กระบวนการหลักคือ:

```text
ไฟล์ภาพ → เปิดเป็น RGB → ปรับขนาด 224 × 224 → Tensor → Normalize
```

| คำศัพท์ | ความหมายง่าย ๆ |
|---|---|
| RGB | ภาพสามช่องสี แดง เขียว และน้ำเงิน |
| Tensor | ชุดตัวเลขที่ใช้แทนพิกเซลภาพและนำไปคำนวณ |
| Normalize | ปรับช่วงค่าตัวเลขด้วยค่าเฉลี่ยและส่วนเบี่ยงเบนมาตรฐานที่กำหนด |

ใช้ค่าเฉลี่ย `[0.485, 0.456, 0.406]` และส่วนเบี่ยงเบนมาตรฐาน `[0.229, 0.224, 0.225]`

ชุด Train มี **Data Augmentation** คือสุ่มพลิกภาพแนวนอน หมุนไม่เกิน 15 องศา และปรับความสว่างหรือคอนทราสต์ระหว่างอ่านภาพ เพื่อให้โมเดลพบภาพหลายสภาพ โดยไม่จำเป็นต้องบันทึกภาพแปรผันทั้งหมดเป็นไฟล์ใหม่

Validation และ Test ใช้การเตรียมภาพแบบคงที่ ไม่มีการสุ่มแปรภาพแบบ Train

## 8. สร้าง Dataset และ DataLoader

`DogSkinDataset` อ่านภาพพร้อม Label ส่วน `DataLoader` จัดภาพให้เป็นชุดย่อย หรือ **Batch**

โน้ตบุ๊กใช้ `batch_size=32` หมายถึงโดยทั่วไปประมวลผลครั้งละ 32 ภาพ ชุดสุดท้ายอาจมีน้อยกว่า 32 ภาพ

**Epoch** คือการไล่ผ่านข้อมูล Train ครบหนึ่งรอบ ตัวอย่างเช่น 10 Epochs หมายถึงผ่านชุด Train สูงสุด 10 รอบ โดยภาพอาจถูกสุ่มแปรต่างกันในแต่ละรอบ

นอกจากนี้ยังแปลง Label เป็นเลข 0–5 ตามตารางในขั้นที่ 1 เพราะชั้นทำนายคำนวณด้วยดัชนีตัวเลข

## 9. โหลด MobileNetV3-Small ที่ฝึกกับ ImageNet มาแล้ว

หัวข้อ 5.3 ของโน้ตบุ๊กใช้คำสั่ง:

```python
model = models.mobilenet_v3_small(
    weights=models.MobileNet_V3_Small_Weights.DEFAULT
)
```

คำสั่งนี้ใช้โครงสร้างจาก `torchvision` และโหลด **Pretrained weights** หรือน้ำหนักที่ผ่านการฝึกกับ ImageNet มาแล้ว ผลรันแสดงการดาวน์โหลดจากเซิร์ฟเวอร์ PyTorch

**ทำเพื่อ:** นำความสามารถประมวลผลลักษณะภาพที่มีอยู่มาเป็นจุดเริ่มต้น แล้วสอนให้ตอบงานใหม่ เรียกว่า **Transfer Learning**

น้ำหนักตั้งต้นยังไม่ได้ถูกฝึกสำหรับ 6 กลุ่มในโปรเจกต์นี้ จึงต้องเปลี่ยนชั้นทำนายและฝึกกับข้อมูลของงานต่อ

## 10. เปลี่ยนชั้นทำนายให้ตอบ 6 กลุ่ม

โน้ตบุ๊กปิด Gradient ของพารามิเตอร์เดิม แล้วเปลี่ยนชั้นสุดท้ายเป็นชั้นใหม่:

```python
for param in model.parameters():
    param.requires_grad = False

in_features = model.classifier[3].in_features
model.classifier[3] = nn.Linear(in_features, num_classes)
```

ในงานนี้ `in_features` เท่ากับ 1024 และ `num_classes` เท่ากับ 6 พารามิเตอร์ของชั้นใหม่เปิดให้ฝึกตามค่าเริ่มต้น และ Optimizer ถูกกำหนดให้ปรับเฉพาะชั้นนี้

```text
ภาพ → ส่วนประมวลผลภาพของ MobileNet → ชั้นทำนายใหม่ → คะแนน 6 กลุ่ม
```

**สิ่งที่ได้:** MobileNet ที่มีรูปแบบผลลัพธ์ตรงกับงาน แต่ชั้นทำนายใหม่ยังต้องเรียนรู้จาก Train

## 11. ฝึกด้วย Train ตรวจด้วย Validation และบันทึก .pth

กระบวนการในแต่ละ Batch:

```text
ภาพ + Label จริง
      ↓
โมเดลทำนาย
      ↓
คำนวณ Loss จากความต่างระหว่างคำทำนายกับคำตอบจริง
      ↓
คำนวณ Gradient และปรับน้ำหนักของส่วนที่เปิดให้ฝึก
      ↓
ทำ Batch ถัดไปจนจบ Epoch
```

ค่าหลักที่ใช้ในโน้ตบุ๊ก:

| รายการ | ค่า / หน้าที่ |
|---|---|
| Loss | `CrossEntropyLoss` วัดความผิดพลาดในการจำแนกกลุ่ม |
| Optimizer | `AdamW` ปรับพารามิเตอร์ชั้นทำนายใหม่ |
| Learning rate | `0.001` กำหนดขนาดการปรับน้ำหนัก |
| Weight decay | `0.01` เป็นส่วนหนึ่งของการควบคุมการเรียนรู้ |
| จำนวนรอบสูงสุด | 10 Epochs |
| Mixed Precision | ช่วยลดภาระการคำนวณบนอุปกรณ์ที่รองรับ |
| Early Stopping | หยุดหาก Validation loss ไม่ดีขึ้นติดต่อกัน 3 รอบ |

เมื่อจบแต่ละ Epoch จะประเมิน Validation โดยไม่ปรับน้ำหนัก ถ้า Validation loss ต่ำกว่าที่ดีที่สุดก่อนหน้า จะบันทึกด้วย:

```python
torch.save(model.state_dict(), '/content/best_dog_model.pth')
```

**นี่คือจุดที่สร้างไฟล์ .pth ของงานนี้** ไฟล์ถูกบันทึกได้ตั้งแต่ระหว่างฝึก และถูกเขียนทับเมื่อน้ำหนักชุดใหม่ผ่านเกณฑ์ที่ดีกว่า

ผลรันที่เก็บไว้ฝึกครบ 10 Epochs และเลือกน้ำหนักจาก **Epoch ที่ 9** ตาม Validation loss ไม่ใช่เลือกจาก Accuracy สูงสุด

### .pth เก็บอะไร และภาพทั้งหมดไปไหน

ไฟล์นี้เก็บ `state_dict` ซึ่งมีค่าน้ำหนักและสถานะของชั้นต่าง ๆ ไม่ใช่ ZIP ที่บรรจุภาพ และไม่ได้เก็บประวัติการฝึกหรือชื่อกลุ่มทั้งหมดไว้ด้วย

| สิ่งที่เก็บ | อยู่ที่ไหนตามกระบวนการในโน้ตบุ๊ก |
|---|---|
| ชุดภาพหลังทำความสะอาด | ZIP บน Google Drive ในขั้นที่ 5 |
| ภาพที่แตกไว้เพื่อฝึก | `/content/dog_skin_dataset/` บนเครื่อง Colab |
| น้ำหนักที่เลือก | `/content/best_dog_model.pth` |

พื้นที่ `/content` เป็นพื้นที่ชั่วคราว จึงต้องดาวน์โหลดหรือสำรองไฟล์ที่ต้องการเก็บก่อนเครื่อง Colab ถูกรีเซ็ต การฝึกไม่ได้ทำให้ภาพต้นฉบับกลายเป็น `.pth` หรือหายไปเพราะถูกบันทึกเป็นน้ำหนัก

## 12. ประเมินน้ำหนักที่เลือกด้วย Test

หัวข้อ 5.5 โหลด `best_dog_model.pth` กลับเข้า MobileNet แล้วทำนายภาพ Test ทั้ง 1,902 ภาพ โดยไม่ปรับน้ำหนัก

| สิ่งที่ตรวจ | ใช้ตอบอะไร |
|---|---|
| Accuracy | ทำนายถูกโดยรวมกี่ส่วน |
| Precision | เมื่อทายว่าเป็นกลุ่มหนึ่ง คำทายนั้นถูกมากแค่ไหน |
| Recall | ภาพที่เป็นกลุ่มหนึ่งจริง ถูกตรวจพบมากแค่ไหน |
| F1-score | ค่าที่พิจารณา Precision และ Recall ร่วมกัน |
| Confusion matrix | โมเดลสับสนระหว่างกลุ่มใด |

รายงานที่บันทึกไว้แสดง Accuracy ประมาณ **80%** และ Macro F1 ประมาณ **0.79**

**ตัวเลขนี้เป็นผล MobileNet ในการทดลองที่บันทึกไว้เท่านั้น** ไม่ใช่คะแนนของ EfficientNet หรือการรับรองคะแนนของไฟล์ปัจจุบันหลังฝึกต่อ และไม่ใช่คะแนนเปอร์เซ็นต์ที่เว็บแสดงให้ภาพหนึ่งภาพ

## 14. เปิด API และโหลดโมเดลให้พร้อม

`model/main.py` สร้าง API ด้วย **FastAPI** ซึ่งเป็นตัวกลางรับรูปจากหน้าเว็บและส่งผลจาก Python กลับไป

ตัวอย่างส่วนโหลด MobileNet ตามโค้ด:

```python
model_mobilenet = models.mobilenet_v3_small()
model_mobilenet.classifier[3] = nn.Linear(1024, len(CLASSES_LIST))
model_mobilenet.load_state_dict(torch.load(mobilenet_path, map_location=device))
model_mobilenet = model_mobilenet.to(device).eval()
```

| คำสั่ง | หน้าที่ |
|---|---|
| `mobilenet_v3_small()` | สร้างโครงสร้างโมเดล |
| `nn.Linear(...)` | สร้างหัวจำแนกให้ตรงกับน้ำหนัก 6 กลุ่ม |
| `torch.load(...)` | อ่านน้ำหนักจากไฟล์ |
| `load_state_dict(...)` | ใส่น้ำหนักเข้าโมเดล |
| `.to(device)` | ย้ายไป GPU หากใช้ CUDA ได้ หรือใช้ CPU |
| `.eval()` | ตั้งพฤติกรรมชั้นต่าง ๆ เป็นโหมดทำนาย |

EfficientNet-B0 ใช้หลักเดียวกัน โดยปรับ `classifier[1]` แล้วโหลด `efficientnet_model.pth`

ในขั้นนี้ไม่ได้ขอ pretrained weights ใหม่จาก Torchvision เพราะจะใส่น้ำหนักจากไฟล์ของโปรเจกต์อยู่แล้ว ระบบยังโหลด CLIP และตัวเตรียมข้อมูลของ CLIP ด้วย ซึ่งอาจต้องดาวน์โหลดเมื่อยังไม่มีในแคช

เมื่อรัน `main.py` ตามโค้ด API รับการเชื่อมต่อที่ `http://127.0.0.1:8000` การเปิด API ตามปกติเป็นการโหลดน้ำหนัก ไม่ได้เริ่มฝึกใหม่

## 15. ผู้ใช้เลือกรูปบนเว็บ แล้ว React ส่งรูปให้ API

หน้าที่ใช้งานจริงคือ `../frontend/src/features/analysis/pages/CheckPage.jsx` โดยแยก `predict()` ไป `../frontend/src/features/analysis/services/prediction-api.js` หน้าเว็บตรวจไฟล์ JPG, PNG หรือ WEBP ขนาดไม่เกิน 10 MB แสดงภาพตัวอย่าง และส่งภาพเมื่อผู้ใช้กดเริ่มวิเคราะห์

ข้อมูลสัตว์เลี้ยงที่เลือก เช่น ชื่อ พันธุ์ และอายุ ใช้ประกอบการแสดงผลบนเว็บ แต่คำขอทำนายปัจจุบันส่งเฉพาะรูป จึงยังไม่ได้นำข้อมูลเหล่านี้เข้าโมเดล

## 16. API อ่านภาพและใช้ CLIP คัดกรอง

API อ่านไฟล์เป็นภาพ RGB ถ้าอ่านไม่ได้จะส่งข้อผิดพลาดกลับ จากนั้นเรียก `check_is_dog_or_lesion()` ซึ่งใช้โมเดล `openai/clip-vit-base-patch32`

CLIP เปรียบเทียบความสอดคล้องระหว่างภาพกับข้อความ เช่น ภาพสุนัข ภาพผิวหนังหรือรอยโรค ภาพแมว และภาพสิ่งของ

โค้ดใช้ทั้งภาพต้นฉบับและภาพปรับแสง รวมคะแนนข้อความฝั่งที่ยอมรับ แล้วเลือกค่าที่สูงกว่าระหว่างสองภาพ หากคะแนนนั้นไม่น้อยกว่า `0.45` จึงให้ผ่าน

**สิ่งที่ได้:** การตัดสินให้ผ่านหรือปฏิเสธ ก่อนจำแนกกลุ่มผิวหนัง ข้อความบางรายการครอบคลุมผิวหนังสัตว์หรือรอยโรคทั่วไป จึงไม่ใช่การยืนยันชนิดสัตว์หรือคำตอบอย่างแน่นอน

หากไม่ผ่าน API ส่งสถานะ 400 พร้อมข้อความให้ผู้ใช้เลือกภาพใหม่

## 17. สร้างภาพ 6 รูปแบบสำหรับทำนาย หรือ TTA

ฟังก์ชัน `build_tta_batch()` สร้างภาพจากภาพอัปโหลดเดียวกัน:

| ลำดับ | รูปแบบ |
|---:|---|
| 1 | ภาพต้นฉบับ |
| 2 | ภาพปรับแสง คอนทราสต์ และความคม |
| 3 | ภาพปรับแล้วตัดขอบ เน้นกลางภาพ เมื่อภาพใหญ่พอ |
| 4 | ภาพปรับแล้วผ่านตัวกรองเพิ่มความคม |
| 5 | ภาพปรับแล้วเพิ่มความสว่างและคอนทราสต์ |
| 6 | ภาพปรับแล้วกลับแนวนอน |

แต่ละภาพถูกปรับเป็น `224 × 224` แปลงเป็น Tensor และ Normalize ก่อนรวมเป็น Batch เดียว

วิธีนี้เรียกว่า **Test-Time Augmentation หรือ TTA** เพื่อพยายามลดความไวต่อสภาพภาพ ต้องประเมินเพิ่มเติมจึงจะรู้ว่าช่วยงานนี้เท่าไร การเพิ่มความคมไม่รับประกันว่าจะกู้รายละเอียดที่หายจากภาพเบลอได้

**TTA เป็นการทำนายหลายมุมมอง ไม่ใช่การฝึกใหม่ และไม่ปรับน้ำหนัก**

## 18. MobileNet และ EfficientNet คำนวณคะแนน

`predict_with_model()` ประมวลผลภาพทั้ง 6 รูปแบบของแต่ละโมเดล:

```python
with torch.no_grad():
    outputs = m(input_batch)
    probabilities = torch.softmax(outputs, dim=1).mean(dim=0)
```

ลำดับคือประมวลผลภาพ ใช้ `softmax` แปลงผลเป็นคะแนนของแต่ละกลุ่ม แล้วเฉลี่ยคะแนนจากทั้ง 6 รูปแบบ **ภายในโมเดลเดียวกัน**

จากนั้นใช้ `IDX_TO_CLASS` แปลงดัชนี 0–5 เป็นชื่อกลุ่ม และเรียงคะแนนจากมากไปน้อย

โมเดลใช้ค่าน้ำหนักคำนวณจากภาพใหม่ ไม่ได้ค้นหาภาพที่เหมือนกันในรูปฝึก 13,415 ภาพ และไม่จำเป็นต้องโหลดชุดภาพฝึกทั้งหมดเพื่อทำนาย

การเตรียมภาพ ลำดับชื่อกลุ่ม และโครงสร้างโมเดลต้องเข้ากับน้ำหนัก หากสลับลำดับชื่อกลุ่ม ผลที่แสดงอาจผิดชื่อได้แม้โหลดน้ำหนักสำเร็จ

## 19. เลือกผลที่จะส่งกลับเว็บ

API คำนวณผลทั้งสองโมเดลที่โหลดได้ และพิมพ์ผลเปรียบเทียบใน Terminal ก่อนเลือกผลตอบกลับตามโหมด:

| โหมด | ผลตอบกลับเมื่อโมเดลที่ขอพร้อมใช้งาน |
|---|---|
| `model_type=mobilenet` | ผล MobileNet |
| `model_type=efficientnet` | ผล EfficientNet |
| `model_type=both` หรือ `POST /compare` | ผลทั้งสองโมเดลแยกกัน |
| `auto` ซึ่งเป็นค่าเริ่มต้น | เลือกตามลำดับความพร้อมในโค้ด |

หน้าเว็บปัจจุบันไม่ส่ง `model_type` จึงใช้ `auto` โดยโค้ดเลือก EfficientNet ก่อนเมื่อโหลดน้ำหนักที่มีหัวจำแนก 6 กลุ่มได้ หากไม่เข้าเงื่อนไขจะเลือก MobileNet แล้วจึงใช้ EfficientNet ที่มีอยู่เป็นทางเลือกท้ายสุด หากไม่มีโมเดลพร้อมจะส่งข้อผิดพลาด

ตัวแปร `efficientnet_is_finetuned` ถูกตั้งจากจำนวน Outputs ในไฟล์ **การมี 6 Outputs ยังไม่ใช่หลักฐานว่าฝึกได้ดีหรือมีความแม่นยำตามเกณฑ์**

**ปัจจุบันไม่ได้เฉลี่ยคะแนนระหว่าง MobileNet กับ EfficientNet เป็น Ensemble** การเฉลี่ยในขั้นที่ 18 เป็นคะแนนจาก 6 ภาพภายในแต่ละโมเดลเท่านั้น

ผลปกติของหน้าเว็บส่งกลับเป็น JSON ที่มีรายการ `label` และ `score` ตัวอย่างเฉพาะรูปแบบหนึ่งรายการคือ `{"label": "healthy", "score": 0.8}` ตัวอย่างนี้ไม่ใช่ผลทำนายจริง

## 20. React นำผลมาแสดงบนหน้าเว็บ

เมื่อ API ตอบกลับ `Check.jsx` ตรวจว่าผลเป็นรายการ แปลงคะแนนเป็นตัวเลข เรียงคะแนน แล้วเก็บไว้ด้วย `setResult(predictions)` และเปลี่ยนสถานะเป็น `done`

สิ่งที่หน้าเว็บแสดง:

- รูปที่ผู้ใช้อัปโหลดและชื่อสัตว์เลี้ยงที่เลือก
- ชื่อกลุ่มที่ได้คะแนนสูงสุด โดยแปลงเป็นภาษาไทยผ่าน `diseaseName()`
- คะแนน 3 อันดับแรกเมื่อเปิดดูรายละเอียด
- คำแนะนำที่อ่านจาก `ADVICE` ในโค้ด
- ป้ายความเสี่ยงจากกฎที่กำหนดไว้บนหน้าเว็บ

คำแนะนำเป็นข้อความที่เตรียมไว้ ไม่ได้สร้างโดยโมเดลภาษา ปัจจุบัน `ADVICE` มีรายการ `Skin Infection` และ `default` ส่วนชื่อ 6 กลุ่มจาก API ไม่ตรงกับ `Skin Infection` จึงใช้คำแนะนำ `default` ตามโค้ดนี้

ป้ายความเสี่ยงคำนวณดังนี้:

| เงื่อนไข | ป้ายที่แสดง |
|---|---|
| ผลหลักเป็น Healthy | ต่ำ |
| กลุ่มอื่นและคะแนนตั้งแต่ 0.70 | สูง |
| กลุ่มอื่นและคะแนนตั้งแต่ 0.40 แต่ต่ำกว่า 0.70 | ปานกลาง |
| กลุ่มอื่นและคะแนนต่ำกว่า 0.40 | ต่ำ |

เกณฑ์นี้เป็นกฎในหน้าเว็บ ยังไม่ใช่โมเดลที่ฝึกเพื่อประเมินความรุนแรง คะแนนเปอร์เซ็นต์ของภาพหนึ่งภาพก็ไม่ใช่ Accuracy ของระบบหรือโอกาสเป็นโรคที่ผ่านการสอบเทียบแล้ว

หาก API เชื่อมต่อไม่ได้ อ่านภาพไม่ได้ หรือคัดกรองไม่ผ่าน หน้าเว็บแสดงข้อผิดพลาด การทำนายจากหน้าตรวจจริงไม่ได้ใช้ผลตัวอย่างแทนเมื่อ API ล้มเหลว

## การฝึกต่อหลังได้ .pth: เป็นกระบวนการแยกจากการตรวจภาพ

โปรเจกต์มีโค้ดฝึกต่อสองวิธี แต่หน้า `Check.jsx` ปัจจุบันเรียกเฉพาะ `/predict` ไม่ได้เรียกวิธีเหล่านี้อัตโนมัติ

| วิธี | ลำดับที่โค้ดทำ |
|---|---|
| `POST /learn` | รับภาพพร้อม `true_label` → เก็บใน `model/learned_data/<กลุ่ม>/` → สร้าง Batch 14 ภาพแปรผัน → เปิดให้ฝึก Feature ส่วนท้ายและ Classifier → ปรับน้ำหนัก 3 ขั้น → บันทึกทับ .pth ของโมเดลที่มีอยู่ |
| รัน `retrain_batch.py` | รวบรวมภาพจาก `DATA_DIR` และ `learned_data` → เลือกสูงสุด 35 ภาพต่อกลุ่ม → สำรองน้ำหนักเดิมเป็น `_backup.pth` → ฝึกส่วนท้ายของทั้งสองโมเดลตัวละ 4 Epochs → บันทึกทับไฟล์หลัก |

`DATA_DIR` ของสคริปต์ยังชี้ไปยังโฟลเดอร์บนเครื่องผู้พัฒนาเดิม จึงไม่ได้ยืนยันว่ามีชุดข้อมูลนั้นอยู่บนเครื่องปัจจุบัน และสคริปต์นี้ไม่ได้อ่าน ZIP 13,415 ภาพจาก Colab โดยอัตโนมัติ

เส้นทางฝึกต่อทั้งสองแบบยังไม่มีการประเมิน Validation/Test ก่อนบันทึกทับแบบโน้ตบุ๊กเดิม การฝึกเพิ่มจึงยังไม่ยืนยันว่าคะแนนดีขึ้น ต้องประเมินไฟล์น้ำหนักหลังฝึกต่อแยกต่างหาก

## แยกให้ออกระหว่างสิ่งที่มีโค้ดแล้วกับสิ่งที่ยังไม่เชื่อม

| เรื่อง | สถานะตามหลักฐานที่ตรวจ |
|---|---|
| ขั้นตอนฝึก MobileNet ครั้งแรก | มีในโน้ตบุ๊กที่อ้างอิง |
| ขั้นตอนฝึก EfficientNet ครั้งแรก | ยังไม่พบหลักฐานในไฟล์ที่ตรวจ |
| ทำนายผ่าน Python API | มีโค้ดรับภาพและทำนายจริง |
| ใช้ข้อมูลพันธุ์และอายุประกอบโมเดล | ยังไม่ได้ส่งข้อมูลเหล่านี้เข้า `/predict` |
| รวมคะแนนสองโมเดล | ยังไม่มี Ensemble ในเส้นทางปัจจุบัน |
| เรียนรู้จากทุกภาพที่อัปโหลด | ไม่มีใน `/predict` ต้องเรียกการฝึกต่อแยก |
| บันทึกผลตรวจจริงลงประวัติ | หน้าเว็บยังอ่าน `HISTORY` ที่เป็นข้อมูลตัวอย่าง ไม่ได้เพิ่มผลใหม่จาก `/predict` |
| เชื่อมฐานข้อมูลกับการทำนาย | มีไฟล์ออกแบบฐานข้อมูล แต่เส้นทางทำนายปัจจุบันยังไม่บันทึกลงฐานข้อมูล |

## คำศัพท์สำหรับกลับมาทบทวน

| คำ | ความหมายในงานนี้ |
|---|---|
| Dataset | ชุดภาพพร้อมข้อมูลประกอบ |
| Label / Class | คำตอบหรือชื่อกลุ่มของภาพ |
| CNN | กลุ่มสถาปัตยกรรมโครงข่ายที่ใช้ประมวลผลภาพ |
| Architecture | โครงสร้างโมเดล เช่น MobileNetV3-Small |
| Weights | ค่าตัวเลขที่โมเดลใช้คำนวณและปรับระหว่างฝึก |
| Pretrained | ผ่านการฝึกกับชุดข้อมูลอื่นมาแล้ว |
| Transfer Learning | นำโมเดลที่มีความรู้เดิมมาต่อยอดกับงานใหม่ |
| Loss | ค่าความผิดพลาดที่ใช้เป็นเป้าหมายในการฝึก |
| Overfitting | เรียนรู้ภาพฝึกได้ดี แต่ใช้กับภาพใหม่ได้ไม่ดี |
| Inference | นำโมเดลและน้ำหนักมาใช้ทำนาย |
| TTA | ทำนายภาพเดียวกันหลายรูปแบบแล้วรวมผลภายในโมเดล |
| API | ช่องทางให้หน้าเว็บส่งรูปไปให้ Python และรับผลกลับ |
| JSON | รูปแบบข้อมูลที่ API ใช้ส่งผลให้หน้าเว็บ |
